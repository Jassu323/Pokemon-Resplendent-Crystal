# Selected Pokedex Internal Transition Investigation

Investigated 2026-10-01 against `9855e86b8` (`Cry Playback Bug Fixes`). Scope:
`DEX-TRANS-01`, `DEX-TRANS-02`, and `DEX-TRANS-03`. Option 3 was subsequently
integrated and tested on 2026-10-01. The baseline investigation and private
prototypes below are historical evidence; the
[implemented handoff](#implemented-internal-handoff) records the final-link
results. The animation scheduler, 96-tile startup lead, and 32-block sampled-cry
prefill remain unchanged.

## Summary

Two baseline causes are established:

1. Palette staging briefly requests a hardware update before the new maps are
   ready. A VBlank in that interval exposes the incoming picture/type graphics
   under the outgoing textual identity. Five normal-input transitions reproduce
   this for two or three completed display frames.
2. Internal paging blacks out early, then prepares row-padded owner maps but
   publishes through the slower general backing copier instead. That copier's
   scanline waits, repeated transfers and separate reveal wait prolong staging.

Private copied-ROM prototypes establish that a request-free palette stage
removes every reproduced mixed-page frame. Reusing the existing maps for an
atomic publication shortens navigation; postponing blackout until RAM-only
preparation finishes further shortens the visible black interval. No new
animation production model or audio throughput change is indicated.

## Cause: Premature Palette Publication

The CGB branch of `PokedexSelectedMon_StageDescription` in
[pokedex_detail.asm](../engine/pokedex/pokedex_detail.asm) performs:

1. Build incoming backing text, base graphics, footprint, type graphics and
   animation startup.
2. Call `CGB_PokedexStageSelectedMonLayout` to build attributes/native palettes
   and copy palette targets with `ApplyPals`.
3. Call `Pokedex_ApplyUsualPals`.
4. Clear `hCGBPalUpdate`.
5. Stage and publish the maps.

Step 3 calls `DmgToCgbBGPals($e4)` and `DmgToCgbObjPal0($e0)` in
[home/palettes.asm](../home/palettes.asm). Both request hardware publication by
setting `hCGBPalUpdate`. Clearing it in step 4 does not protect the intervening
instructions from VBlank. The generic palette service can restore the colors
while the old maps still refer to already-overwritten static graphics.

For Heracross-to-Koffing, the trace is unambiguous:

| Boundary | T-cycle | LY | Palette request |
| --- | ---: | ---: | ---: |
| Native layout staged | 8,312,540 | 122 | 0 |
| Usual-palette conversion entered | 8,312,840 | 122 | 0 |
| Premature hardware palette flush | 8,323,068 | 145 | 1 |
| Usual-palette conversion returned | 8,342,944 | 34 | 1 |
| Owner map staging begins | 8,343,420 | 35 | 0 |
| General backing publication begins | 8,408,308 | 24 | 0 |
| Intended reveal begins | 8,558,808 | 46 | 0 |

The premature flush occurs at a legal palette-write time. There are no blocked
palette writes in the reproduced cases. This is a publication-order bug, not
the earlier Listing palette-transfer overrun and not an animation underrun.

The palette-only prototype replaces this one staging call with a request-free
helper. `$e4` is the identity BG mapping, so the native palette targets already
copied by `ApplyPals` do not need another eight-palette conversion. It retains
the usual BGP/OBP0 values and OBJ0 conversion through existing `CopyPals`, without
setting the hardware-update flag. Across 373 transitions this removes all five
premature flushes and every visible staging frame, without disabling interrupts
for the entire conversion.

## Cause: Redundant Publication And Early Blackout

`PokedexSelectedMon_ChangeSpecies` cancels outgoing cry/animation ownership,
then immediately calls `PokedexSelectedMon_BeginHiddenTransition`. Text redraw,
base-picture decompression, footprint preparation, uploads and animation
startup all run after the screen is black.

`Pokedex_PublishOrStageDescriptionBacking` in
[pokedex_3.asm](../engine/pokedex/pokedex_3.asm) builds the existing 576-byte
tilemap and 576-byte attrmap buffers in WRAMX bank 3. Listing-to-Selected uses
those buffers through the owner publisher. Internal paging instead falls
through to `Pokedex_CopyBackingToBG`:

- `CopyTilemapAtOnce` waits for LY 127 or later.
- It copies attributes and tiles through separate STAT-guarded CPU transfers.
- It waits for LY 127 again before returning.
- Description column 20 is copied separately.
- `PokedexSelectedMon_Reveal` requests palettes and waits another frame.

Representative elapsed costs include interrupts and scanline waits; these are
not isolated instruction-only budgets:

| Section | Bayleef -> Meganium | Dusclops -> Dusknoir |
| --- | ---: | ---: |
| Base RAM preparation | 171,964 T | 157,244 T |
| Animation startup | 188,784 T | 354,224 T |
| Row-padding existing owner maps | 65,152 T | 65,164 T |
| General backing publication | 158,336 T | 132,708 T |
| Separate reveal wait | 55,144 T | 55,224 T |

The row-padded buffers are **not disposable**: subsequent animation map updates
depend on them. Reuse them for the initial internal-page reveal rather than
removing their preparation or keeping a second full-screen publication path.

Text/base/footprint preparation can occur while the outgoing display remains
visible, because it changes backing RAM, scratch WRAM and SRAM, not the current
VRAM picture. Blackout must still precede static-picture uploads, type uploads
and startup work that can overwrite displayed allocations. This is not a
proposal to upload arbitrary animation work over the outgoing page.

## Private Prototype Comparisons

Three private variants isolate the effects:

- `palette-only`: request-free palette staging; original map copier/reveal.
- `fast-maps`: palette fix plus two GDMA map transfers and BG palette reveal
  in one admitted VBlank; skip the redundant separate reveal wait.
- `late-hide`: the above plus RAM preparation before blackout, immediately
  followed by hidden static VRAM commitment.

The atomic prototype copies both 576-byte maps and all 64 BG palette bytes in
**3,884 T-cycles** at normal speed. Across the 373 settled transitions it enters
44-72 T-cycles after physical VBlank starts and finishes on LY 152, leaving
604-632 T-cycles before visible scanning resumes. Palette writes are unblocked.
The Selected page has no visible OAM objects; this private commit does not copy
OBJ palettes or perform unnecessary OAM DMA. B-return restores Listing's actual
used OBJ palettes through its existing independent publisher.

For isolation, the prototype admits this commit from a mainline LY-143 wait,
then briefly disables interrupts and checks VBlank admission. This is **not**
a recommendation to drop that exact polling wrapper into production. The
existing VBlank owner dispatcher is the preferable integration point, with
its real entry overhead included in final timing validation.

## Fix Options, Costs And Recommendation

| Option | Benefit | ROMX estimate | Complexity / tradeoff |
| --- | --- | ---: | --- |
| Request-free palette stage only | Removes reproduced mixed identity/stale badges | 32-byte private helper | Low; long hidden preparation remains |
| Palette fix + atomic internal publication | Same cleanup, roughly 2-3 fewer navigation intervals in focused controls | About 0.25-0.35 KiB total | Moderate, contained; still blacks out before RAM preparation |
| Above + delayed blackout | Same correctness, shortest measured visible blackout | About 0.25-0.35 KiB total | Moderate; must enforce the RAM-only/displayed-VRAM ownership boundary |

The assembled all-feature private overlay is 296 bytes: 55 in bank `$a0`
(palette/prepare/reveal adapters), 241 in bank `$77` (publication/admission).
The accepted map has 2,331 and 2,843 free bytes in those banks respectively.
No new bank or ROMX asset dataset is needed. Production can reuse existing
helpers instead of retaining the experimental wrappers, so 296 is not a claimed
final net size.

All options require **zero additional ROM0, WRAM0, WRAMX, HRAM or VRAM**. The
two 576-byte owner buffers, existing palette targets and owner-request byte
already exist. Adding an internal-transition request value does not require
another byte. Current animation staging slots and dictionaries remain intact.

**Recommendation: implement the palette fix, atomic publication and delayed
blackout together as one narrowly scoped internal-page handoff.**

Suggested production integration:

1. Give Selected palette staging a local request-free helper; do not alter the
   global DMG-to-CGB conversion routines or the unrelated Listing publisher.
2. Move internal-page hiding until after RAM-only base/footprint preparation
   and before static VRAM commitment. Guard this behavior by the switching-
   species state, not every caller of the shared preparation helper.
3. Queue an internal Description owner transition using the existing staged
   maps. Honor its completion/carry contract in `ChangeSpecies`, avoiding the
   general copier and duplicate `Reveal` wait.
4. Add a Selected-only publication profile in the existing owner dispatcher.
   It must include incoming frontpic palette 1. The current cold-entry
   Description palette branch begins at palette 2 and cannot be reused unchanged.
5. Publish the two maps plus BG palettes 0-2 and 6-7, the palettes actually used
   by this page. Skip unused OBJ/OAM work for this sprite-free handoff, without
   changing Listing's sprite restoration. This narrower payload provides more
   reserve than the private all-eight-BG-palette proof.
6. Admit only a sufficiently early VBlank; retain the outgoing/black display
   and retry when late. Measure the full dispatcher return and first dependent
   scanline, not only the palette loop. Keep bank restoration and incoming
   animation start after publication completes.
7. Rerun all-species cold/internal/active/return suites on the final link, then
   visually check the five reproductions and heavy transitions in-game.

Main risks are admitting too late, accidentally publishing incomplete maps,
moving a VRAM write before blackout, omitting a used palette, or applying the
new internal profile to a different owner. Existing state/request guards and
the full-link regression suite address these without another scheduler change.

A completely black-free handoff would require separate incoming display
storage or safe scanline-specific replacement of more assets. Duplicating the
base alone needs 49 tiles, plus footprint/type ownership as applicable, and
borrowing animation slots risks the established startup lead. That is a larger
VRAM/lifetime redesign, not recommended for this cleanup.

## Implemented Internal Handoff

Option 3 is now in the normal `pokecrystal.gbc` build, not an overlay or an
alternate runtime branch. Implementation is confined to
`engine/pokedex/pokedex.asm`, `pokedex_detail.asm`, and `pokedex_3.asm`.

### Order And Ownership

1. `PokedexSelectedMon_ChangeSpecies` accepts the destination, cancels the old
   cry and animation owner, and uses the existing warm-transition helper to
   hold maps, palette publication and OAM. "Warm" here means retaining the old
   display; it does not add a neighboring-species cache or background prefetch.
2. Incoming text, base-picture decompression and footprint RAM preparation run
   while the outgoing page remains frozen and visible. No displayed VRAM is
   overwritten by this preparation.
3. After `Pokedex_PrepareSelectedMonTiles`, the switching-species path calls
   `PokedexSelectedMon_BeginHiddenTransition`. Blackout completes before
   `Pokedex_CommitPreparedSelectedMonGFX`, type uploads or animation startup can
   replace shared displayed graphics. The DMG fallback retains early hiding.
4. The unchanged animation priming routine fills only its normal startup
   deficit. Native layout staging and `ApplyPals` build incoming attributes
   and targets. `PokedexSelectedMon_StageUsualPals` retains BGP `$e4`, OBP0 `$e0`
   and the usual OBJ0 conversion without requesting hardware palette updates;
   the identity BG conversion is already supplied by native staging.
5. `Pokedex_PublishOrStageDescriptionBacking` completes the existing two
   576-byte owner buffers, then queues the new
   `POKEDEX_OWNER_TRANSITION_INTERNAL_DESCRIPTION` request value in the existing
   owner byte. Generic backing publication is not used for this transaction.
6. The existing VBlank dispatcher admits the request only at `144 <= LY < 145`,
   with no pending generic map/DMA transfer. It publishes both complete maps
   and the 40 palette bytes actually used by Description: BG 0/1/2/6/7. This
   profile includes incoming frontpic palette 1, unlike the cold Listing entry
   profile. There is no visible OBJ content, so internal publication skips OBJ
   palettes and OAM DMA. Listing retains its separate protected profile.
7. The publisher restores WRAM/VRAM banks, clears the request/dirty flags and
   returns carry. The mainline waits for completion and skips its former
   redundant `Reveal` wait. Incoming cry/animation start only afterward.

The visibility boundary is state-guarded inside the Selected staging path,
not moved into the shared `Pokedex_PrepareAndCommitSelectedMonGFX` wrapper.
Unrelated Listing preparation therefore retains its own contract. The selected
native palette helper also protects cold-entry staging from the same premature
request race, without changing global palette conversion routines.

## Buffered Icons In Production

Accepted and integrated 2026-10-01. This replaces the private return-repair ROM,
not another runtime option or alternate build path. The outgoing shell, text,
footprint and type badges stay visible during internal Description paging;
only the shared portrait region is white while its graphics are replaced.
The incoming footprint and badges are uploaded off-screen into their alternate
tile set. The existing atomic owner publication reveals the complete incoming
page, including its matching icon palettes, in one admitted VBlank.

### Tile Ownership And Return Repair

| Set | Footprint, VRAM bank 1 | Type badges, VRAM bank 1 |
| --- | --- | --- |
| A | `$8b10-$8b4f`, signed BG IDs `$b1-$b4` | `$9640-$96bf`, IDs `$64-$6b` |
| B | `$96c0-$96ff`, IDs `$6c-$6f` | `$9700-$977f`, IDs `$70-$77` |

1. Cold Description entry resets the selector to set A. The selector reuses
   `wPokedexWRAM0ScratchEnd - 1` (`$cd13`), outside the maximum order-seen bitset.
   No byte is removed from padding and no RAM section grows.
2. Internal paging reads the outgoing footprint's backing-map tile ID before
   constructing the new page. It selects the other set, then enters the existing
   frozen-display transition. Selection is based on displayed ownership rather
   than a blindly incremented counter.
3. Static picture preparation stays RAM-only until the portrait mask is visible.
   Footprint commitment chooses set B only for a CGB Selected switching/Area
   state with the B selector; normal Listing callers still use set A.
4. Type upload and placement use the same selector. Both type badges and all
   four footprint tiles therefore belong to one coherent incoming set. The
   incoming maps are staged before publication; neither outgoing icon set is
   overwritten while its map is still displayed.
5. Writing set B invalidates the normal resident-footprint species tag with
   zero. It does not use `$ff`, which has separate absent-footprint semantics.
   A tag may not claim that set A contains a newly prepared set-B footprint.
6. B-return restores the current species' normal set-A footprint during the
   existing hidden return transaction. This preserves Listing cache reuse and
   prevents a later cold Description entry from reusing a stale set-A image.
   An A-entry tag mismatch also has a footprint-only repair path; it does not
   force a complete frontpic/grid rebuild.
7. Area return uses the shared state-guarded destination rules. The focused
   round-trip tests verify both buffer selections, but do not certify every
   historical Area presentation issue.

The implementation is confined to the Dex modules. It does not change the
global sound/palette code, the authored animation timelines, the 96-tail-tile
startup lead, the two 49-tile animation stages, or the 32-block sampled-cry
prefill and eight-block refill policies. DMG retains its original footprint
and early-hidden fallback rather than using CGB buffer B.
